Ingestion

IoT density sensors (BLE/WiFi) → Pub/Sub → Cloud Dataflow → BigQuery real-time table. Ticketing API webhooks stream gate scans. 1-second aggregation window.

ML Model

Vertex AI AutoML time-series forecasting trained on 200+ historical match-days. Features: zone density, gate throughput, weather, team rivalry score. 15-min horizon, retrained weekly.

API Contract
GET /api/v1/crowd/density → { zones: [{id, density, capacity, trend}] }
GET /api/v1/crowd/predict?horizon=15m → { predictions: [{zone, t+5, t+10, t+15}] }
POST /api/v1/crowd/alerts → triggers Pub/Sub staff notification
Privacy

No PII collected. Sensors count aggregate bodies, not individuals. No facial recognition. Data retained 90 days for model training, then purged. GDPR Article 6(1)(f) — legitimate interest.

Ingestion

POS system integration via Pub/Sub. Overhead camera people-counters per stand. BLE beacons for queue length estimation. 5-second update cycle.

ML Model

Gradient boosted trees (XGBoost on Vertex AI) predicting wait times. Features: current queue, service rate, time-of-day, match phase. Virtual queue uses priority scheduling algorithm.

API Contract
GET /api/v1/queues → { stands: [{id, name, waitMinutes, queueLength, countersOpen}] }
POST /api/v1/queues/virtual/join → { ticketId, position, estimatedWait }
WS /api/v1/queues/virtual/status → real-time position updates
Privacy

Virtual queue uses anonymized ticket IDs. Queue imagery processed on-device, no cloud storage. Transaction data aggregated, no individual purchase history retained beyond session.

Ingestion

Venue BIM model converted to navigation graph. BLE beacon network for indoor positioning (±2m accuracy). Crowd density layer from Module 1 overlaid on routing weights. Google Maps Platform Indoor Maps API.

Routing Algorithm

Modified A* pathfinding with dynamic edge weights. Congestion factor multiplies path cost by (1 + density²). Accessibility mode restricts to wheelchair-accessible edges (lifts, ramps, wide corridors ≥1.5m).

API Contract
POST /api/v1/navigation/route → { from, to, accessible, densityAware } → { path: [{point, instruction}], distance, eta }
GET /api/v1/navigation/poi → { points: [{id, type, name, location, floor}] }
Privacy

BLE positioning computed on-device. Server receives only origin/destination for routing — no continuous location tracking. Route history not persisted. Offline routing via cached graph.

Ingestion

Staff mobile app GPS/BLE for positions. Incident reports via app push. Walkie-talkie integration via speech-to-text. Shift schedules from HR system via API. All streamed through Pub/Sub.

ML Model

Staffing optimization model (Vertex AI custom training): predicts zone demand 20 min ahead using crowd density + historical incident rates + match phase. Outputs optimal staff distribution per team.

API Contract
POST /api/v1/incidents → { type, location, severity, description } → { incidentId, assignedTeam, assignedStaff }
GET /api/v1/staff/positions → { staff: [{id, team, location, status}] }
GET /api/v1/staff/suggestions → { suggestions: [{zone, team, staffNeeded, reason}] }
Privacy

Staff location tracked only during active shifts, consent-based. Incident reports pseudonymized for training. Performance metrics aggregated at team level, not individual. 30-day retention for operational data.
